### 2. 本 fork 任务"学会技能"机制（关键，踩坑记录）

- **语义（用户确认）**：RewSpell = **任务让角色学会的法术**（写进技能书的那个）；RewSpellCast = **对玩家释放一次的法术**。
- **本 fork SPELL_EFFECT_LEARN_SPELL = 36**（不是标准的 53！见 src/game/Spells/SpellEffectDefines.h:62）。
- 学会发生在"释放载体法术"时：Spell::EffectLearnSpell 读 **EffectTriggerSpell**（SpellEffects.cpp）→ player->learnSpell。
- 任务奖励流程（Player.cpp RewardQuest，~13516 行）：
  - spellId = RewSpellCast; if (!spellId) spellId = RewSpell; 然后对玩家 CastSpell(spellId, TRIGGERED_OLD_TRIGGERED)
  - 即：有 RewSpellCast 就释放 RewSpellCast（载体）；没有才退而释放 RewSpell。
- **正确设计（方案 A）**：RewSpell = 31892/31801（学会的圣印本体，客户端原生显示"你学会了"）；RewSpellCast = 91010/91011（载体，Effect1=36 + EffectTriggerSpell1=圣印），释放一次触发学会。
- 骑术示例：RewSpell=33388（学会的骑术）、RewSpellCast=33389（载体，Effect1=36+Trigger=33388）→ 施放 33389 学会 33388。
- 库内另一变体（种族技能任务）：RewSpell=19338（载体本身带 36 效果）、RewSpellCast=0 → 退而释放 RewSpell，学会其 EffectTriggerSpell=13908。此变体把载体放 RewSpell，奖励图标显示 19338（客户端 DBC 存在所以正常）；自定义载体放 RewSpell 则图标"未知"→ 所以圣印任务用方案 A（载体放 RewSpellCast）。
- TRIGGERED_OLD_TRIGGERED 施放**不发客户端动画** → 载体法术对客户端完全不可见，无显示瑕疵。

  Antispam.Enable=1。
- **Warden**：warden_modules 已部署 219 个扫描模块（.bin/.cr/.key），ScanFrequency=15s。
  - 本地 Warden.Enable=1，**云端 Warden.Enable=0**（历史遗留，见下"超时掉线已修复"）。
  - **超时掉线问题已修复（commit b501fb3d，2026-08-14 "修改warden"）**：此前 Warden 超时（客户端 30 秒
    内未正确回复）会 `KickPlayer()` 踢人，导致部分客户端（精简/修改版，无法正确回复 Warden）掉线。

    （停止本会话 Warden 计时，**不再踢人**）。
  - 注意：warden.cpp 其余 KickPlayer（119/127/369/380/387/402/425/433/480/487 行）是**作弊检测**路径
    （模块校验失败/协议异常/可疑 EndScene hook 等），与超时无关，检测到作弊仍会踢。
  - 另外该 commit 给 config 加了 `GetWardenEnabled()`：`Warden.Enable=0` 时 `_warden=nullptr`
    （libanticheat.cpp），Warden 完全不初始化；=1 时正常初始化扫描。

### 实测发现（2026-08-21，穿门补丁客户端）
- **客户端自带防修改检测（farmdoor 诱饵）**：穿门补丁客户端进游戏触发
  `ERROR #131 (0x85100084) File: world\generic\...\farmdoor01test.m2` → 客户端弹窗"Press OK to terminate"并**自行终止**。
  - `farmdoor01test.m2` 是补丁作者/客户端埋的**诱饵检测文件**：正常客户端不会加载它，修改过碰撞的客户端在某区域被触发加载
    → 文件缺失 → 客户端进程内报错自杀。这是**客户端侧机制，与服务器无关**（服务器检测到作弊的表现是踢线，不是客户端弹窗）。
  - 结论：穿门补丁客户端若进游戏前就弹窗终止，服务器端无需处理（它玩不了）；能绕过的话由服务器 Warden/Movement 兜底。
- **客户端无法学习新增技能 = 同类客户端机制（用户确认推断）**：殉难圣印 20000 客户端显示坏、跨阵营圣印训练师不可学，
  根源都在**客户端自身**（Spell.dbc 数据缺失 / 训练师 UI 的 SkillLineAbility.dbc 阵营判定），服务器改不了客户端行为
  → 只能绕开（任务线学技能，即本手册第一章方案二）或客户端打补丁。这与 farmdoor 同属"客户端黑盒"范畴。
- **此前掉线玩家归因（用户确认）**：掉线玩家使用**其他版本客户端**（无法正确回复 Warden 协议/版本不兼容），
  与 b501fb3d 超时踢人→不踢 的修复归因一致；现在超时不踢后这类客户端只会扫描失效，不再掉线。

### Warden 机制澄清（2026-08-21 修正，重要）
> 用户最初理解："反作弊内置 warden 默认开启、检测客户端版本、无 warden 模块被踢、开 warden 后篡改客户端无法游戏"。
> 以下为修正后的准确机制，决策（是否开云端 Warden）以此为准。

1. **Warden 不是默认开启，由配置控制**：`anticheat.conf` 的 `Warden.Enable` 决定——**本地=1（开）、云端=0（关）**。
   `Enable=0` 时 `_warden=nullptr`（libanticheat.cpp `GetWardenEnabled()` 分支），Warden 完全不初始化。
2. **Warden 检测的是客户端完整性，不是版本**：服务器下发加密 .bin 模块，客户端运行后回传校验结果，
   比对 hack 特征（内存扫描 + 文件校验 + EndScene hook 检测）。**客户端版本/build 检查是登录阶段的另一套机制**
   （realmd/World 登录时校验 build），与 Warden 无关。其他版本客户端跑不了模块，表现为"无法回复"，不是"版本检测"。
3. **无法回复 Warden 的客户端不会被踢（b501fb3d 已改）**：旧代码超时 30 秒 KickPlayer 踢线；
   现改为只记录 `"timeout (not kicked)"` + 停止该会话扫描（warden.cpp:495-500）。扫描失效不等于踢线。
4. **"开 Warden 后篡改客户端无法正常游戏"部分成立**：带作弊特征的篡改客户端（穿门/飞行/加速补丁命中扫描）会被踢
   （作弊检测路径 KickPlayer 与超时无关）；**其他版本/无法回复的客户端不踢**（仅扫描失效）。

| 客户端类型 | 服务器反应（当前代码）|
|---|---|
| 官方 2.4.3 客户端 | Warden 正常扫描，无作弊 → 正常游戏 |
| 被篡改且带作弊特征 | Warden 扫描命中 → 踢（作弊检测路径）|
| 其他版本 / 无法回复 Warden | 不踢（超时不踢），仅记录 + 扫描失效 |
| 客户端内置诱饵检测（farmdoor） | 客户端自己弹窗终止，服务器不参与 |

→ **云端开 Warden 安全**：正常玩家不掉线；作弊客户端被扫描命中踢线。

### 反作弊策略（2026-08-21 用户决策）
- **决策：云端不启用 Warden（强制客户端校验会阻挡一部分非原版客户端玩家）**，反作弊以**行为检测**为主。
  - 强制客户端校验（Warden/build 强校验）会挡掉无法回复 Warden / 其他版本客户端的玩家 → 放弃，玩家优先。
