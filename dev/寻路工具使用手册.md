# 寻路工具使用手册（mmap / navmesh / viewer）

> 面向"我要查一个点为什么走不过去 / 这张图的寻路长什么样 / 重新烘一遍"的日常操作。
> 只写**怎么用**；数据格式、轴序、实现细节见 `dev/tools/README_mmtile_vis.md`，
> 结论与踩坑历史见 `dev/KNOWN_ISSUES.md` 的 `[寻路/地形]` 章。
>
> 所有工具都在 `dev/tools/`（⚠️ 被 `.gitignore` 忽略，**不进 git**）。
> 数据在 `x64_Debug\`：`mmaps/`（导航网格）`maps/`（地形）`vmaps/`（建筑碰撞）。

---

## 0. 这套工具能干什么

| 我想… | 用这个 | 一句话 |
|---|---|---|
| **看**某张图的导航网格长什么样 | `mmtile_vis.py --serve` | 浏览器里的 3D 查看器（地形+建筑+导航+生物） |
| 查**某个坐标**为什么走不过去 | 查看器里点一下 / `?map=&gy=&gx=&x=&y=` | 面板给"可达 N 面 / 缺口 X 码" |
| 看某点在 **Recast 内部**长什么样 | `mmap_dump_probe.py` | 读 `.tri/.rawhf/.chf/.pmesh` 转储 |
| 找**孤岛**、看能不能连 | `spawn_link.py --link-islands --report-only` | 统计"太远/太陡/被墙挡住/门隔开" |
| **补连**孤岛 | `spawn_link.py --link-islands` | 生成 off-mesh 表，再由生成器读入 |
| **重新烘焙** mmap | `MoveMapGen.exe --workdir <沙盒>` | ⚠️ 永远烘到沙盒，绝不直接写 `x64_Debug\mmaps` |
| 给每张图出**二维小地图** | `mmtile_vis.py --minimaps <dir>` | 72 张 PNG + index.html |

## 1. 查看器 `mmtile_vis.py`

### 1.1 启动

```powershell
cd D:\Game\cmangos\Nmangos-tbc\dev\tools
python mmtile_vis.py --map 530 --serve --port 12000
```

- **端口别用 8870~9069**（Windows 保留段，绑定会报 `WinError 10013`）。日常用 **12000**。
- 换一份数据（例如沙盒里刚烘的）加 `--mmap-dir`：

```powershell
python mmtile_vis.py --map 530 --serve --port 12000 --nav-offset 0.06 `
  --mmap-dir D:\Game\cmangos\_agent_tmp\all_run\work\mmaps
```

⚠️ **重启查看器时要按 PID 杀**，不要 `Get-Process python | Stop-Process`（会连带杀掉其它 python）：

```powershell
(Get-NetTCPConnection -LocalPort 12000 -State Listen).OwningProcess | ForEach-Object { Stop-Process -Id $_ -Force }
```

### 1.2 URL

```
http://127.0.0.1:12000/?map=530
```

左上角下拉切地图（`--serve` 模式下是单端口多地图）。**改了 `--mmap-dir` 之后必须硬刷新（Ctrl+F5）**，否则列表还是旧的。

### 1.3 图层开关（2026-10-18 精简后只剩这些）

| 按钮 | 作用 |
|---|---|
| **建筑 开/关** | WMO/M2 碰撞模型显隐 |
| **寻路叠加** | 导航网格（绿线）。**下面一行 `☑ 含陡坡面`** 控制 STEEP（area 10）要不要画 |
| **水域** | WATER(9) / MAGMA(8) 的面（关了只看陆地） |
| **落地/重力** | 打开＝重力+立即落回地面；关闭＝自由飞行（原「落回地面」「重力」合并） |
| **生物/巡逻** | 刷点球 + 巡逻线 + **连锁组着色**（同色＝同一批） |

> 已删除：清除选择 / 坏面 / 陡坡（并入寻路叠加）/ 波形推进 / 细节网格 / 待烘焙 off-mesh / 导出 SQL / 恢复原序。
> 对应的 JS 函数还在，只是按钮拿掉了。

### 1.4 加载范围 与 连通性半径

面板底部两个下拉框：

| 下拉 | 选项 | 说明 |
|---|---|---|
| **加载范围（格）** | 3×3 / 5×5 / 7×7 / 9×9 / 11×11 | 3×3 ≈ 1600 码见方。**大陆图别开大**，网格会悬在没有地形的地方 |
| **连通性半径（码）** | 250（大陆默认）/ 500 / **800（副本推荐）** / 1200 | `/conn` 抓多大圆盘的面。**副本里 250 会显示不全**，用 800 |

### 1.5 跳到指定点

"跳到指定位置"输入框接受游戏内命令，直接粘：

```
.go xyz -156.6 -326.8 17.1 555
```

回车后视角落到那个坐标。**GPS 行的含义**：

```
GPS  X -156.6  Y -326.8  高度 17.1  格 32_32　导航面 #1935 (c=0)
```

- **`格 32_32`** = `gy_gx`（注意是**先 gy 后 gx**）
- **`c=0` = 可达**，`c=2` = 不可达
- 指到导航面才显示面号；只指到地形就只显示坐标

### 1.6 连通性结论怎么看

面板里"起点 #xxxx（可达 N 面）"：

| 显示 | 含义 |
|---|---|
| **可达区域很大（N 面），未算缺口** | 通到主网格了 ✓ |
| **缺口 X 码** | 附近有另一个分量，差 X 码没连上（配 `dist` 圆盘看） |
| **可达面很小（几面~几十面）** | **孤岛** —— 去 §3 跑 `spawn_link.py` |

### 1.7 生物 / 连锁组着色

打开「生物/巡逻」后，同色球体 = 同一批怪。分组来源**按优先级**：

1. **`_agent_tmp/dungeon_route_wave_mobs.tsv`** 的 `group_id`（站长指定，副本首选）
2. 没有表 → `creature_linking` / `creature_linking_template`
3. 同族互助：同 `family` 且在 `CreatureFamilyAssistanceRadius`（`mangosd.conf`，默认 **5 码**）内
4. **巡逻怪不参与**第 3 条（它们有自己的路线颜色）

调色板是**固定 8 色循环**（红/蓝/黄/青/橙/紫/绿/粉），超过 8 组从头再来。

## 2. 定点探针 `mmap_dump_probe.py`

回答"这个坐标在 **Recast 内部**是什么样"：三角、原始高度场 span、紧凑高度场、轮廓、多边形。

### 2.1 先拿到转储

```powershell
$env:MMAP_DEBUG_DUMP = 'D:\Game\cmangos\_agent_tmp\dump'
MoveMapGen.exe --workdir <沙盒> "555"      # 只烘 555
```

产物（每个 533 码 tile × 625 个子格）：

| 后缀 | 内容 |
|---|---|
| `.tri` | 喂给 `rcRasterizeTriangles` 的三角 + area 标记 |
| `.rawhf` | 光栅化后的原始高度场（span 链） |
| `.chf` | 紧凑高度场 |
| `.contour` | `rcBuildContours` 输出 |
| `.pmesh` | `rcBuildPolyMesh` 输出（`s-1-1` 是**合并后的整块**） |

⚠️ 全量转储约 **7.7 GB**，跑完记得清。

### 2.2 查一个点

```powershell
python mmap_dump_probe.py --dump D:\...\dump --map 555 "--at=-156.67,-326.80" --z 17.13
```

- `--at` 是**世界 X,世界 Y**；**必须以 `--at=` 形式写**，否则 PowerShell 会把 `-156` 当参数
- `--z/--zr` 给一个关心的高度和容差，输出会给偏离的面打 ⚠️
- `--near N` 连邻近子格一起扫（子格之间有 border 重叠）

## 3. 孤岛与补连 `spawn_link.py`

### 3.1 只看不动（推荐先跑这个）

```powershell
python spawn_link.py --mmap-dir <dir> --only 530,543 --link-islands `
  --small-max-polys 40 --max-dh 2 --report-only
```

输出形如：

```
map 555 需处理岛 5：连上 0（顶点 0）| 面数>=40 的 0，太远 4，太陡 0，门隔开 0，被墙挡住 0
```

| 桶 | 含义 | 对策 |
|---|---|---|
| `面数>=40` | 岛太大，不是"小孤岛" | 调参数或查几何 |
| `太远` | 到主网格硬边界顶点超过 `--max-dh` | 放宽 `--max-dh` |
| `太陡` | 坡度 > `--max-slope`（默认 45°） | **这类不该补**，多半是台沿 |
| `门隔开` | 附近 20 码有 GameObject（门） | 门会挡住视线 |
| `被墙挡住` | `vmap_los_probe` 判定直线穿墙 | **正确拒绝**，别硬连 |

### 3.2 真补（生成表，不写库）

```powershell
python spawn_link.py --mmap-dir <dir> --only 555 --link-islands --out offmesh_555.txt
```

表格式（生成器读这个）：

```
<map> <tileX>,<tileY> (X Y Z) (X Y Z) 0.5
```

烘焙时传 `--offMeshInput <表>`。**改参数时别忘了这个参数**（历史上就因此丢过一张表，见 KNOWN_ISSUES）。

### 3.3 关键实现点（改代码前必读）

- **端点量的是"主网格的硬边界顶点"**（`neis == 0` 的那条边的端点），不是面中心。
  量面中心会天然多出半个面的距离，1.5/2 码这种阈值几乎全判"太远"。
- **逐顶点搭桥**，不是从质心发散（质心发散会形成星形枢纽，怪必须走到岛心才用得上）。

## 4. 重新烘焙 `MoveMapGen`

### 4.1 永远烘到沙盒

```powershell
$w = 'D:\Game\cmangos\_agent_tmp\run1\work'
New-Item -ItemType Directory -Force -Path $w, "$w\mmaps"
cmd /c mklink /J "$w\maps"  "D:\Game\cmangos\x64_Debug\maps"
cmd /c mklink /J "$w\vmaps" "D:\Game\cmangos\x64_Debug\vmaps"

$env:MMAP_DEBUG_DUMP = ''      # 不要转储
Push-Location $w               # ⚠️ 必须在 workdir 里启动（config.json 的读取位置，见 4.2）
& 'D:\Game\cmangos\build1\bin\x64_Release\Extractors\MoveMapGen.exe' --workdir $w "530"
Pop-Location
```

- **不写 `--map` 参数 = 全部 72 张图**（约 9~15 分钟）
- **只烘副本**：把 `tbcmangos.instance_template` 的 59 个 map id 拼成一个字符串传进去
- **`--tile` 参数顺序是 `gy,gx`**，而内部 `loadMap(mapID, tileX, tileY)` 要 `(x,y)` ——
  写反了会去加载另一个 tile，然后**静默退出**。`5302619`（gy=26 gx=19）必须写 `--tile 19,26`。

### 4.2 ⚠️ `config.json` 的两个坑（踩过四次）

```cpp
// generator.cpp
const char* configInputPath = "config.json";   // ① 相对**当前工作目录**，不是 --workdir
// MapBuilder.cpp → getMapIdConfig()
std::string key = std::to_string(mapId);       // ② 必须按地图 ID **嵌套**
if (m_config.find(key) != m_config.end())      //    平铺的配置根本不会被读到
    config.merge_patch(m_config.at(key));
```

正确写法（放在**启动时的 CWD** 里，也就是 workdir 根）：

```json
{ "530": { "terrainSlopeAngle": 90.0, "walkableClimb": 5, "minRegionArea": 10 } }
```

**教训：改配置做对照实验时，先证明配置真的生效**（改一个会反映到 `.mmtile` 头里的值看变不变），
否则"结果一模一样"只说明参数没进去。

### 4.3 生成参数当前默认（`MapBuilder::getDefaultConfig`）

| 键 | 默认 | 说明 |
|---|---|---|
| `walkableClimb` | **5**（1.3333 码） | 1.18 码的台沿要能上去 |
| `walkableRadius` | **0**（不侵蚀） | 站长口径："擦墙走是对的"。也会写进 `.mmtile` 的 agent 半径 |
| `minRegionArea` | **60** | ⚠️ **不要设 0**。Recast 是两步：① 小于 `mergeRegionArea` 的并进邻居 ② 小于 `minRegionArea` 的**删掉**。设 0 后第 ② 步不砍，碎块全留下、各自成孤岛。实测 553 生态船 entry 17980 刷点：`60` → 835 面连通 ✓，`0` → 7 面孤岛 ✗ |
| `mergeRegionArea` | 50 | 太小先并进邻居 |
| `walkableSlopeAngle` | 60 | **模型**（WMO/M2）的坡度上限 |
| `terrainSlopeAngle` | 90 | **ADT 地形**专用，默认不限制坡度 |
| `splitTerrain` | false | 地形/模型分开高度场。**小图有效（530 连通块 856→7165），大图会 0xC0000005 崩溃 ⇒ 默认关** |

### 4.4 烘完怎么验

```powershell
# 1) 有没有静默丢格
findstr /C:"[TILE-EMPTY]" /C:"[TILE-FAILED]" /C:"No polygons to build" build.log

# 2) .mmap 的 maxPolys 必须是 65536（0x80000000 是溢出 bug）
python -c "import struct;d=open('530.mmap','rb').read(28);print(struct.unpack_from('<2i',d,20))"

# 3) 逐格面数对比（新旧两份 .mmtile）
python mmtile_probe.py --compare <旧目录> <新目录>
```

| 标记 | 含义 |
|---|---|
| `[TILE-EMPTY]` | 地形和 vmap 都没读到几何 ⇒ 这格本来就没数据 |
| `[TILE-FAILED]` | `dtNavMesh::addTile` 失败 ⇒ 整格没写盘（旧版会静默 continue） |
| `No polygons to build on tile!` | 有几何但过滤后没有可走面 |

## 5. 坑速查

| 症状 | 真因 |
|---|---|
| 端口起不来，`WinError 10013` | 8870~9069 是 Windows 保留段 |
| 查看器看不到地形/寻路 | 之前的 python 被杀干净了；按 PID 重启（§1.1） |
| 换了 `--mmap-dir` 但地图列表没变 | 没硬刷新（Ctrl+F5） |
| 副本里"有些地形显示不全" | 连通性半径 250 太小，切 **800** |
| 改 `config.json` 结果完全没变化 | CWD 不对 / 没有按地图 ID 嵌套（§4.2） |
| `--tile` 烘出来是空的 | 参数顺序写反了（§4.1） |
| 生成器跑完报 complete 但少了格 | 有 `[TILE-EMPTY]`/`[TILE-FAILED]`，需要扫日志 |
| 大面积消失 / 大图崩溃 | `splitTerrain` 打开了大图（0xC0000005），保持 false |
| `AuctionHouseMgr::AddAItem` 断言导致起服失败 | 与 mmap 无关，是 AHBot 的拍卖行重复项；本地二进制旧、需重编 |
