# dev 文档导航（按主题查阅）

> 新会话只需项目根 `AGENTS.md`；本页用于查技术结论或修改技术文档，不要求每次全文读取。先搜主题/符号，再读正文所需小节。这里不重复修复结论、不滚动堆放历史更新摘要。

## 〇、书写规范
- 技术问题、运维结论和代码验收统一并入 `KNOWN_ISSUES.md` 既有主题，同一主题一章；误报不记，dev 不另立技术 md（站长点名除外）。记录前先与站长确认；站长已明确要求的文档整理直接执行。
- 章节用 `## [分类] 名称`，复用正文现有分类。内部按现象、根因/来源、修复、验证证据与覆盖范围、实际缺口组织；不把计划写成已完成，也不堆部署状态标签。
- 结论必须有一手证据；区分实现、编译、离线测试和游戏实测。代码定位写 `文件 → 符号名()`；旧结论被取代须注明日期与替代内容，不抹掉历史事实。
- 新主题才开新章；新增/合并/改名后同步本页索引。仅更新正文小节时，不在导航另抄一份进度。
- 本页及总账随源码提交，禁止写云端 IP、密钥路径、口令等敏感信息；那些只在工作区根本地交接。
- 宣发、视频脚本与角色设定留各自项目；原始日志、报告、失败与负对照保留为证据，第三方资料与工具使用指引保持原入口。
