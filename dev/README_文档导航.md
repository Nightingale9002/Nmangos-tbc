## 〇、KNOWN_ISSUES.md 章节书写规范（新增/改动章节时照着来）

- **章节标题**：`## [分类] 名称 — YYYY-MM-DD 状态`；状态用「已修（本地/云端）」「待修」「分析，未改」「搁置」等明确词。
- **分类词表**（**已在使用，优先复用；要造新词先跟站长确认**）：
  `[地图] [机制] [寻路] [内存] [任务] [水移动] [资源] [平衡] [数据] [配置] [天赋] [部署] [稳定性] [战术] [性能] [待办]`
  `[修复] [本地化] [运维] [经济] [掉落] [核心] [技术]`
- **章节内部建议结构**：`### 现象` → `### 定位/根因（带证据：库字段值、源码文件:行号、日志原文）` → `### 修复（对应 SQL/代码文件）` → `### 验证（本地测了什么、云端是否已部署）` → `### 待办/残留风险`
- **必须留证据**：涉及"是谁的问题"的结论要写清 ID 命名空间（生物 entry / GO entry）、源码位置、日志原文，避免后人重复排查或反向"修错"。
- ⚠️ 本文件**随源码提交 git**：**不要写**云端 IP、SSH 密钥路径、数据库密码等敏感信息（那些留在本地 handoff）。
- **新增章节后同步本文件的第二节章节索引表**（行号会随插入漂移，只作定位提示，不必强求精确）。
