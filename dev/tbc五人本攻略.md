### 副本原则

出什么打什么，有什么躲什么，拉住加好猛揍，万变不离其宗；然后再根据自身情况和队伍组成评估对于难点你们要怎么处理。  
除了风筝等例外情况，战斗中没被控场的怪默认坦克都要做好仇恨。  
高危控场、AA 风筝、卡视角聚怪，都是基本，永远不要吝于使用你的功能性技能。  
TBC 的 5 人副本最不合理的地方就是很多小怪的近战物理伤害经常高得吓人，但只要能风筝 几乎都是瓜。  
一群怪同时存在多个高危小怪，处理不来但可以控场，就应该控著打；有失控技能 (如恐惧) 的怪群，应该拉到离其他怪群比较远的地方打。  
怪只要打不到人读不出条就不能威胁玩家的生存，这些牵制手段就是功能性技能，包括但不限于控场、打断、定身和缓速风筝等。  
例如：要打断一个施法条，除了用断法技能如拳击脚踢之外，还可以是晕、甚至是读羊恐和怪比施法条速度。

## 流程一览

### 副本介绍

黑色沼泽俗称 18 波，因为玩家靠近麦迪文触发战斗后会不间断地出怪，每 5 波小怪就有一次首领战，总共 18 波战斗。

与入副本入口处的萨艾特交谈可以取得一次性消耗品 [时空道标]，召唤一名时光守卫者，施放 [沙尘吐息] 协助玩家与恒龙战斗，持续 30 秒。

因为三个副本 boss 免疫 [沙尘吐息]，一般会将 [时空道标] 用于压力大的那几波小怪，比如第 11 波和第 13~17 波中出了裂隙守卫者的那几波。

场地中有些原生动物：暗水鳄鱼、黑牙狼蛛与潜行的黑虎，牠们本身没什么威胁，但可能干扰玩家吃喝恢复上座骑，建议开战前将活动范围附近的动物们清理掉，或每到一个裂隙就顺手拉过来一起 A 掉。

### 战斗流程

靠近麦迪文会触发战斗，15 秒后开启第一个时光裂隙，开始出怪；之后的整个副本都无法被中断，除非灭团重来。

每一个时光裂隙有 2 分钟战斗时间，超过会自动开启下一个裂隙；如果在时限前击杀裂隙大怪，下一个裂隙会在 15 秒后开启。

第 6 和 12 波对应首领战斗，则有大约 2 分钟休息时间。

每一个时光裂隙开启后都会出现一只守门大怪，并周期性出现小怪直奔麦迪文，攻击并削减他的护盾；击杀大怪才能关闭该裂隙。

当麦迪文的护盾降至 0% 时死亡、即代表整场副本失败灭团，而他会在 5 分钟后重生。

重新开始战斗又要从第一波开始打起。

### 怪物一览

守门大怪：裂隙领主、裂隙守卫者

每个裂隙一只，纯正门神，免疫所有控场缓速打断。

- 裂隙领主：标准的战士怪，[雷霆一击]、[击倒]、[断筋]、[致死打击]、20% 血量时会 [暴怒]。

## 五、副本/BOSS 战策略（机器人"按 BOSS 自动挂载"）— 2026-10-16

> 目标：把 BOSS 攻略（机制 / 站位跑位 / 目标优先级 / 停手·大招·驱散·打断）变成**数据**，
> 让 bot 打到哪个 BOSS 就自动套上那套规则；**不改战斗代码**，只加一个"挂策略"的钩子。
> 数据件：`dev/179_BOSS战策略表.sql`；工具：`dev/tools/`（见 §4）；规则源与生成脚本在 `_agent_tmp/`（不提交）。

### 1. 机制：为什么不改战斗代码

模块里本来就有「自定义策略」引擎（`playerbot/strategy/CustomStrategy.cpp`）：

- 一个策略名 = 一组规则行，格式 `<触发器> > <动作>[!权重], 动作2, ...`
  （`toTriggerNode()` / `toNextActionArray()` / `toNextAction()`）；
- 规则行存角色库 `tbccharacters.ai_playerbot_custom_strategy(id, name, idx, owner, action_line)`；
- **bot 查不到自己的行（`owner` = bot guid low）会自动回落 `owner = 0`**
  （`CustomStrategy.cpp → InitNonCombatTriggers()` → `LoadActionLines(0)`）
  ⇒ BOSS 策略只写 `owner = 0` 一份，全服 bot 立刻生效，**改数据不用重启**；
- 引擎侧键名 = `custom::<name>`（`CustomStrategy.h → getName()`），
  由 `PlayerbotAI::ChangeStrategy("+custom::boss_x")` → `Engine::addStrategy()` 挂载；
- 规则行里的名字**逐字**匹配 `creators["..."]`（`NamedObjectContext.h → NamedObjectFactory::Create()`）——
  写错**不报错、静默失效**，所以必须过校验器（§4）。
- ⚠️ **空格**（2026-10-16 E 组发现 + 已修）：`CustomStrategy.cpp` 原来用不 trim 的 `split()`，
  所以 `触发器 > 动作`（两边带空格）会让名字带尾/前导空格 ⇒ 两个名字都查不到 ⇒ **整条规则静默失效**；
  `val::` 表达式末尾多一个空格还会让 `getMultiQualifiers()` 的 `substr(1,size-2)` 剥错括号（有崩服风险）。
  **现在两头都做了**：① `CustomStrategy.cpp → TrimRuleToken()` 统一 trim（两种写法都能用）；
  ② 生成 SQL 时统一写成模块自带的**无空格**形式（`a>b,c!w`），所以**老二进制**上也安全。

### 2. 两类集：通用集 + 专属集（2026-10-16 站长口径）

**通用行为只写一份**，不要每个 BOSS 重抄一遍：

### 2.1 角色精细分工（2026-10-16 追加：**转火这类规则只有 DPS 生效**）

**两套并存**（站长口径），各有适用面：

| 方案 | 怎么写 | 适用 |
|---|---|---|
| **A. 集名后缀** | `boss_<entry>_dps` / `_tank` / `_healer` / `_melee` / `_ranged`，多个=与（`boss_18371_dps_melee`） | **整个集都只给某角色**：数据自解释，不用编引擎 |
| **B. 规则内复合值** | `val::and::{trigger::<触发器名>,is dps}` | **集里只有某几条限角色**，或角色要和别的条件（触发器/取反）复合 |

两套的实现：

- **A**：钩子 `BossStrategyHook.h → RoleAllows()` 在**挂载时**过滤（后缀里有不认识的名字 ⇒ 该集不挂）。
- **B**：新增 `strategy/values/BossRuleValues.h`（注册在 `ValueContext.h`）：

  | 名字 | 语义 |
  |---|---|
  | `is tank` / `is healer` / `is dps` | 角色；`is dps` = 既非坦克也非治疗（引擎没有现成 `IsDps()`） |
  | `is melee` / `is ranged` | 近战 / 远程（`PlayerbotAI::IsMelee/IsRanged`） |
  | `trigger::<触发器名>` | **把任意触发器当布尔值用的桥**（`TriggerAsValue`，创建一次并缓存） |

  因为 `val` 是"把限定词当值名求值"的通用触发器、`and`/`or`/`not` 是值运算符，所以能写
  `val::and::{trigger::has aura::spellid::36383::greater or equal::4,is melee,is dps}`。

第一批规则按这个口径分配（13 个集 / 21 条规则 / 13 个登记 BOSS）：

|---|---|---|

| A 后缀 | `boss_17536_dps` / `boss_17537_dps` / `boss_17380_dps` | `not behind target > set behind!20`（正面锥只让 DPS 绕背） |

| B 复合 | `boss_18373` | `val::and::{trigger::has nearest adds,is dps} > attack least hp target!62`；`val::and::{trigger::target critical health,is dps} > attack!65` |
| B 复合 | `boss_18667` | 规则1 全员；规则2 `val::and::{trigger::enemy too close for melee,is ranged} > reach spell!60`（只让远程拉开） |

### 3. 钩子实现（本批唯一代码改动）

`PlayerbotAI.cpp → UpdateBossStrategy()`（放在匿名命名空间里，**不动头文件**；由 `UpdateAIInternal()` 尾部每 tick 调用）：

- **限流**：每个 bot 每 5 秒（`BOSS_STRATEGY_CHECK_INTERVAL`）看一次；BOSS 名单每 5 分钟（`BOSS_STRATEGY_LIST_REFRESH`）重扫 DB；
- **找 BOSS**：扫队伍成员（含真人）的 `GetVictim()` 与选中目标（`GetSelectionGuid()`），
  命中 `boss_<entry>` 或登记表 → 挂 `custom::boss_common*` + `custom::boss_<entry>`；
  脱战 / 换目标 / 死亡 → `-` 全部摘掉；
- **自愈**：用 `HasStrategy()` 当权威，bot 重登 / `ResetStrategies()` 清掉后会补挂；
- **多线程**：`MapUpdate.Threads = 3`（本服），共享表全部加锁（`bossStrategyMutex`）；
  每个 bot 的状态键用 `PlayerbotAI*`，`~PlayerbotAI()` 里 `erase(this)`（不解引用正在析构的 bot）；
- **日志**：`[BOSSSTRAT] <bot> +custom::boss_common` / `-custom::boss_<entry>`（`sLog.outString`，落 `Server.log`）；
- **开关**：`AiPlayerbot.BossStrategies`（默认 1；`PlayerbotAIConfig.cpp → Initialize()` 读，模板已写进 `aiplayerbot.conf.dist.in`）。
  关掉 = 完全回到原状（挂载逻辑空转）。

### 6. 「做不到」的机制（实证清单 —— 以后加触发器照这个做）

| 攻略里常见的指令 | 为什么数据层做不到（证据） |
|---|---|
| "BOSS 开反射盾/虚空形态/免疫时停手" | 没有"**目标身上有 aura**"这类触发器：`GenericTriggers.h → HasAuraTrigger::GetTargetName()` 恒为 `"self target"`，只能查自己。缓解：`GenericSpellActions.cpp → CastSpellAction` 内已有"目标反射 >50% 就拒绝施法"的静态保护，近战平砍没有 |
| "BOSS 读条就打断" | 没有"**敌方在读条**"的通用触发器（只有卡拉赞等专用触发器）；打断由职业策略 `pummel/kick/counterspell/...` 自己判断 |
| "躲开脚下的地板/AOE 区" | `move away from hazard` / `void zone too close` / `specific creature too close` 都依赖**副本专用 hazard 列表**与 `set avoid area` 状态，通用规则没有入口。引擎自带的 `avoid aoe` 反应策略只覆盖"自己身上有 area debuff" |
| "被击退/被拉过去之后先别回去" | 位移事件不留 aura、没有"延迟 N 秒"的动作 |
| "只让坦克 / 只让远程做 X" | **2026-10-16 已解决**：用集名后缀 `_dps` / `_tank` / `_healer` / `_melee` / `_ranged`（见 §2.1）。仍然做不到的是"具体某个玩家"这类条件（点名谁、谁装备如何） |
| "坦克把 BOSS 背对人群 / 非近战别站正面" | 站位与朝向没有规则行入口；`not behind target > set behind` 会让坦克也绕圈（更糟） |
| "被心控/被恐惧/被昏迷时怎么应对" | 被控期间机器人不接受自己的 AI 指令（`AttackAction::isPossible()` 排除 `UNIT_FLAG_CLIENT_CONTROL_LOST`）；`charmed/stunned/feared` 触发器在**已中招之后**才成立 |
| "给被点名的队友驱散" | 驱散触发器只查自己（`CureTriggers.h → NeedCureTrigger::GetTargetName()` = `"self target"`），且没有"对队友施放驱散"的通用动作 |
